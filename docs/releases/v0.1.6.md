# Upgrading to 0.1.6

Version 0.1.6 enables delegated application access from a provider embedded
under its configured mount. It uses `bherila/auth-laravel` 0.28.7 or later for
the corresponding consumer-side assertion verification. The browser package
and delegated contract version 3 are unchanged.

## Embedded issuer identity

An embedded provider's issuer includes its mount, for example
`https://app.example.test/auth`. Configure
`AUTH_MANAGER_DELEGATED_ACCESS_ISSUER` to that exact issuer and pin the same
value in the consumer's `DELEGATED_ACCESS_ISSUER` and sign-in provider base URL.
The provider accepts only its configured mount; standalone deployments still
reject issuer paths. Consumers continue to reject assertions for a different
origin, mount or subject namespace. Do not remove the path to make a refused
integration appear to work.

The shared verifier accepts canonical HTTPS mount paths in trusted
configuration. Keys, issuer, audience, application, HTTP method, request-body
digest, expiry and replay checks remain required. No keys or endpoints are
discovered from an assertion or browser input.

## Consumer integration and activation

Use the [application connection procedure](../connecting-an-application.md)
and [consumer account cutover](../consumer-account-cutover.md) for explicit
per-application keys, adapter capabilities, write switches, emergency access
and lifecycle evidence. Shared/synthetic fixtures do not authorize a deployed
consumer or a live account migration. A consumer adapter may support only a
subset of capabilities, and removal affects its disclosed access projection,
not necessarily sign-in or account deletion.

There is no new provider migration in this release. A consumer adopting its
own delegated endpoint still needs the shared nonce and receipt tables through
its reviewed host schema update. Keep endpoint and write activation separate
from package installation and preserve replay data during rollback.

Verify the tagged archives' checksums and provenance as described in
[release verification](../releases.md#verifying-a-release). The source ZIP
contains the matching compiled assets. Rollback can disable delegated writes
or restore reviewed configuration; it does not undo prior role edits, identity
deletion or schema changes. Synthetic-login expiry and lifecycle protections
from [0.1.5](v0.1.5.md) remain required.
