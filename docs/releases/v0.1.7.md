# Upgrading to 0.1.7

Version 0.1.7 packages the compatible dependency and build-toolchain updates
merged after [0.1.6](v0.1.6.md). It uses the published `bwh-auth` 0.6.4 browser
artifact and retains `bherila/auth-laravel` 0.28.7. This is a dependency release;
provider authentication, application authority and activation switches are
unchanged.

## Dependencies and packaging

The locked PHP updates retain Laravel 13.42 and WebAuthn 5.3.12, refresh Guzzle
to 8.3.2 and PSR-7 to 3.3, and include phpseclib 4.0.3. The frontend uses React
19.3, Vite 8.3.8, Lucide 1.72 and TypeScript 7, with pnpm 12.18 consistently in
package metadata and CI/release setup. The intentional exact Base UI 1.9 pin is
unchanged.

The browser package's 0.6.4 artifact carries reviewed toolchain and packed-consumer
verification updates. Its API and the existing broad React/Lucide peer ranges are
unchanged; those peer ranges were already present in the published 0.6.3 package.
The exact GitHub artifact URL, lock integrity and pnpm build approval move together.
No unknown package build scripts are approved.

Both tagged archives contain matching compiled provider assets. Consumers should
verify checksums and provenance, pin the stable release and install its packaged
assets through their normal pipeline; see [release verification](../releases.md#verifying-a-release).
The Composer source ZIP excludes dependencies and runtime configuration, so each
host still resolves its own frozen Composer lock and supplies its isolated keys,
session, database and persistent storage.

## Passport and the phpseclib advisory

Passport is intentionally locked to the stable 13.10 release in this update.
Passport 13.11 pins phpseclib exactly to 4.0.1, which is affected by
[GHSA-w3p9-g4p2-h3rr](https://github.com/phpseclib/phpseclib/security/advisories/GHSA-w3p9-g4p2-h3rr).
Passport 13.10 permits the patched phpseclib 4.0.3 within its declared constraint.
The provider's existing `^13.4` Passport requirement remains unchanged; no unstable
branch, alias, fork or audit exception is introduced. A later stable Passport
release can be adopted once it permits a patched dependency and passes CI.

The advisory concerns excessive password-derivation work when parsing untrusted
encrypted key material. Package audit success does not establish whether a
particular deployment exposed an affected parsing path. Keep signing keys and
configuration under the existing trusted-operator boundary.

## Upgrade and rollback

There is no new provider migration in this release. Keep existing configuration,
authentication assurance, issuer/RP bindings and access switches intact. Package
installation does not provision identities, enable delegated access or change a
consumer's sign-in mode. Existing lifecycle protections and the
[consumer cutover prerequisites](../consumer-account-cutover.md) still apply.

Deploy the reviewed dependency update through the normal staged release process.
A rollback can restore the earlier reviewed package and compiled assets; it does
not undo unrelated account changes or prior schema migrations. Check that the
target lock preserves patched phpseclib; do not restore a lock with a known
affected version.
